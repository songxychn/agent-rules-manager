# 架构

## 状态边界

Agent Rules Manager 把状态分成四类：

1. **可同步源**：`schema.json` 与 `profiles/**`。用户所有、对 Provider 中立，适合用 Git 或其他传输方式同步。
2. **生成的 Runtime**：`.runtime/<profile>-<digest>/**`。应用所有、不可变、可复现，不同步。
3. **本机选择**：`current` 以及应用状态里的 `machine.json`。只在本机选择一个 Profile，不同步。
4. **原生投射与备份**：各 Agent 的文件或链接，以及平台应用状态目录中带漂移保护的快照。

```text
                         validate / render
schema + profiles ────────────────────────────────┐
                                                  v
React + Tauri ───────────────────────────────> arm-core <──────── CLI
                                                  │
          ┌────────────────────┬──────────────────┼─────────────────┐
          v                    v                  v                 v
    不可变 Runtime         本机 current 链接      原生路径           本机备份
```

## 规则库状态机

选定目录会在不写入的前提下分类：

- `empty`：不存在，或只含允许的仓库元数据；
- `legacy`：没有 schema，根目录有一份可迁移的普通 `AGENTS.md`；
- `upgrade`：schema v1 规则包，或 schema v2 多文件 Profile；
- `ready`：受支持的单文件 Profile schema v3；
- `conflict`：目录形态不安全、schema 不受支持，或条目类型不受支持。

快照调用从不修复状态。无效清单、缺失文件、重复路径、不安全路径、未托管的迁移条目，以及意外符号链接，一律失败关闭。

## Profile 契约

Profile 是一个目录，目录名必须与 `profile.json.id` 一致。唯一规则源是普通 UTF-8 文件 `AGENTS.md`。Profile 元数据没有可配置的源文件列表。符号链接源会被拒绝。

旧版 v1/v2 列表只在带预览的迁移中读取。文件按原顺序合并，保留各段原文，并补充分隔换行。变更前先备份；未知文件和不安全路径会停止迁移。

当前资源类型是中立的说明 Markdown。Skills、MCP 定义、子代理、凭据、聊天记录和 Provider 登录状态都不在本契约内。

## 渲染契约

生成时读取该 Profile 的 AGENTS.md。输出以生成警告开头，并标明来源：

```markdown
<!-- Generated by Agent Rules Manager. Edit Profile sources, not this file. -->
<!-- Profile: work -->

<!-- Source: profiles/work/AGENTS.md -->
...

```

Profile 摘要包含逻辑路径和精确内容。内容或路径变化会选用另一个 `.runtime/<profile>-<digest>` 目录。Runtime 文件与 `current`、`machine.json` 同属一次受回滚保护的事务；已有 Runtime 内容不符时阻止启用。

源文件变更会使当前 Runtime 变为 `stale`。刷新是对同一 Profile 的显式预览启用。只读快照和焦点刷新不会生成输出。

## 稳定投射入口

`current` 是相对目录符号链接：

```text
current -> .runtime/work-8d9f20b751a4
```

适配器拿到的是 `<library>/current/AGENTS.md`，不是规范化后的 Runtime 路径。切换 Profile 只改 `current`，各 Agent 的原生链接保持稳定。

全局投射与项目投射共用这一本机选择。项目接入是本机链接，不是按项目选择 Profile，也不是可移植的团队规则导出。

只有缺失的 `current`，或解析到本规则库 `.runtime` 目录内的符号链接，才视为托管。普通文件、目录或外部符号链接会阻止启用。当前 Profile id 只存在于本机应用状态，不写入可同步清单。

## 适配器契约

适配器声明 id、显示名、原生目标路径、命令名和配置标记。检测接受 `PATH` 上的命令或已有标记，因为图形界面进程常常继承不完整的 `PATH`。

- 目标缺失或已被识别为托管时，接入可以直接创建符号链接。
- 原生路径上的普通文件仍是合法的独立使用状态。接入它需要明确的接管确认；完整原文会先保存为应用状态 `backups/originals/<snapshot-id>/` 下的可读文件，再替换原生路径。
- 退出托管链接时，会把当前 Profile 内容落成独立的普通文件。
- 旧版托管 include 可安全拆除或迁移。混有或损坏标记的普通文件只能走同一套确认后的整文件备份接管；内容不会被猜测或局部改写。
- 指向外部的符号链接，以及所有不受支持的文件系统条目，仍是硬冲突。

每个适配器必须在不读取认证数据的前提下检查，先导出完整期望状态再变更，校验写入，并且只在目标仍等于预期已应用状态或原始状态时恢复。

## 事务与回滚模型

规则库变更和原生投射使用乐观、失败即关闭的事务：

1. 校验 id 和当前模型；
2. 生成完整预览，把普通文件接管标为需明确确认，并在写入前拒绝非接管冲突；
3. 重新读取每个目标的原始状态；
4. 持久化原文、期望摘要、尚不存在的目录，以及已确认接管文件的可读副本；
5. 应用每个目标并校验其精确状态；
6. 失败时，只恢复仍等于预期状态的已完成目标；
7. 保留快照供显式回滚。

回滚只接受仍匹配预期已应用状态或精确原始状态的目标。第三种状态是应用后漂移，会阻止完整回滚。回滚只删除应用前记录为不存在、且回滚时仍为空的目录；之后出现用户数据的目录保持不动。

删除 Profile 适用同一契约的反向过程：Profile 必须未启用，每个目录条目都必须已声明且为普通文件，所有源文件在移除前先快照。仅在全部文件写入校验通过后，才删除空的自有目录。并发目录变更会立即按该次删除快照回滚。

## v1 升级契约

Schema v1 只当作导入格式，不是现行公开抽象：

- 每个旧 Profile 得到一份 `AGENTS.md`，按旧渲染顺序合并被引用源的内容，并补充分隔换行；
- 旧源文件和清单只在同一次已备份事务内移除；
- 未使用的旧 Pack、未声明的 Pack 条目、符号链接或目标冲突会阻止完整升级；
- 复用已有的本机 Profile 选择，并在迁移后重新渲染；
- 回滚恢复 v1 文件，只删除迁移创建且仍为空的目录。

## 外部编辑边界

WebView 只能请求已知 Profile 声明的源文件，标识为 `(profile_id, relative_path)`，以及后端返回的固定打开目标 id。核心层会再次校验归属，Tauri 层在调用平台适配器前确认其为普通文件。WebView 不能提交可执行文件或任意绝对路径。

浏览器模式使用代表性内存数据。创建或删除 Profile、启用、接入或退出 Agent、回滚都只改这份快照。刷新页面会重置演示；不会访问真实配置文件或外部编辑器。

## 多机器传输契约

未来传输层只接收这份允许列表：

```text
schema.json
profiles/**
```

必须排除 `.runtime/**`、`current`、全部应用状态、Agent 原生路径、备份、凭据和 Provider 登录状态。冲突保持可见；认证由系统 Git/SSH 或其他传输层负责。

## 桌面分发

版本 tag 会构建未签名安装包：macOS DMG（Apple Silicon 与 Intel）、Windows 当前用户 NSIS，以及 Linux `.deb` / AppImage。已安装的桌面应用会检查 GitHub Releases 上的 `latest.json`，并可从设置下载已签名的更新包。Apple 公证和 Authenticode 仍是可选的操作系统信任步骤，不属于文件系统安全契约。

## 扩展点

- 显式 Git fetch/pull/merge/push；
- 在同一事务契约下编辑或重命名 Profile 元数据；
- 可配置的 Agent 检测与目标路径；
- 对独立原生规则的受控导入或归档；
- 说明 Markdown 以外的类型化资源；
- Windows 专用 junction 或复制保证，使 Agent 链接在未开开发人员模式时也能工作；
- 已签名、已公证的桌面发行。
